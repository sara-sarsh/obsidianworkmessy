`pip freeze` shows the **exact packages currently installed in your active Python environment**, usually in a format that can be saved and reinstalled later.

First make sure your venv is active:

```bash
source .venv/bin/activate
which python
which pip
```

Then:

```bash
pip freeze
```

Example output:

```text
aiohttp==3.9.5
requests==2.32.3
websockets==12.0
```

To save it:

```bash
pip freeze > requirements.txt
```

To install from it later:

```bash
python -m pip install -r requirements.txt
```

Small habit upgrade: prefer this form because it guarantees pip belongs to the active Python:

```bash
python -m pip freeze
python -m pip install -r requirements.txt
```

---

## Important: `pip freeze` is not the same as project requirements

`pip freeze` records **everything installed** in the environment, including indirect dependencies.

For example, if you install:

```bash
python -m pip install requests
```

`pip freeze` might show:

```text
certifi==2025.1.31
charset-normalizer==3.4.1
idna==3.10
requests==2.32.3
urllib3==2.3.0
```

Your project only directly asked for `requests`, but `pip freeze` includes all its dependencies too.

That is useful for reproducibility, but not always ideal for clean project maintenance.

---

## Better mental model

There are usually two kinds of dependency files:

```text
requirements.in
```

Human-written list of direct dependencies:

```text
requests
websockets
qrcode
```

```text
requirements.txt
```

Machine-generated locked list with exact versions:

```text
certifi==2025.1.31
charset-normalizer==3.4.1
idna==3.10
qrcode==8.0
requests==2.32.3
urllib3==2.3.0
websockets==12.0
```

For simple projects, `pip freeze > requirements.txt` is okay.

For cleaner advanced management, use `pip-tools`.

# Tool 1: `venv`

This is the built-in standard Python virtual environment tool.

Create:

```bash
python3 -m venv .venv
```

Activate:

```bash
source .venv/bin/activate
```

Check:

```bash
which python
python -m pip --version
```

Deactivate:

```bash
deactivate
```

Remove and recreate:

```bash
rm -rf .venv
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
```

This is the baseline tool. Good to know deeply.

# Tool 2: `pip freeze`

Use it to snapshot the current environment:

```bash
python -m pip freeze > requirements.txt
```

Install snapshot:

```bash
python -m pip install -r requirements.txt
```

Check installed packages:

```bash
python -m pip list
```

Show details about one package:

```bash
python -m pip show requests
```

Show dependency tree? `pip` itself does not do this well. Use `pipdeptree`.

---

# Tool 3: `pipdeptree`

Install:

```bash
python -m pip install pipdeptree
```

Show dependency tree:

```bash
python -m pipdeptree
```

Find why a package is installed:

```bash
python -m pipdeptree --reverse --packages urllib3
```

Example meaning:

```text
urllib3
└── requests
```

This tells you `urllib3` is installed because `requests` depends on it.

Very useful when your environment feels messy.

# Tool 4: `pip-tools`

This is one of the best “advanced but still simple” workflows.

Install:

```bash
python -m pip install pip-tools
```

Create `requirements.in`:

```text
requests
websockets
qrcode
```

Compile locked `requirements.txt`:

```bash
pip-compile requirements.in
```

This generates a fully pinned `requirements.txt`.

Install/sync exactly:

```bash
pip-sync requirements.txt
```

The big advantage of `pip-sync`:

```bash
pip-sync requirements.txt
```

makes your environment match the file exactly. It removes packages that are installed but not listed.

With plain pip:

```bash
python -m pip install -r requirements.txt
```

it installs missing packages, but does not remove extra old packages.

That difference matters a lot.

Good workflow:

```bash
source .venv/bin/activate
python -m pip install pip-tools

# edit requirements.in manually
pip-compile requirements.in
pip-sync requirements.txt
```

For dev dependencies:

```text
requirements.in
requirements-dev.in
```

Example `requirements-dev.in`:

```text
-r requirements.in
pytest
black
ruff
ipython
```

Compile both:

```bash
pip-compile requirements.in
pip-compile requirements-dev.in
```

Sync dev environment:

```bash
pip-sync requirements-dev.txt
```

# Tool 5: `pyproject.toml`

Modern Python projects often put dependency metadata in `pyproject.toml`.

Example:

```toml
[project]
name = "evck"
version = "0.1.0"
dependencies = [
    "requests",
    "websockets",
    "qrcode",
]
```

Then install your project:

```bash
python -m pip install -e .
```

With optional dev dependencies:

```toml
[project.optional-dependencies]
dev = [
    "pytest",
    "ruff",
    "black",
]
```

Install with dev tools:

```bash
python -m pip install -e ".[dev]"
```

For your project, since `setup.py` is inside `opt/evck`, you would run:

```bash
cd opt/evck
python -m pip install -e .
```

or from repo root:

```bash
python -m pip install -e "opt/evck"
```

# Tool 6: `Poetry`

Poetry manages:

- virtual environments
- dependencies
- lock files
- packaging
- publishing

Install usually with:

```bash
pipx install poetry
```

Create project:

```bash
poetry init
```

Add dependency:

```bash
poetry add requests
```

Add dev dependency:

```bash
poetry add --group dev pytest ruff black
```

Install all deps:

```bash
poetry install
```

Run inside environment:

```bash
poetry run python app.py
poetry run pytest
```

Enter shell:

```bash
poetry shell
```

Poetry creates a lock file:

```text
poetry.lock
```

Good for apps and libraries, but it can feel heavier if your existing project is already based on `setup.py` and requirements files.

# Tool 7: `pipenv`

Pipenv is another dependency and venv manager.

Install:

```bash
pipx install pipenv
```

Install package:

```bash
pipenv install requests
```

Install dev package:

```bash
pipenv install --dev pytest
```

Run command:

```bash
pipenv run python app.py
```

It creates:

```text
Pipfile
Pipfile.lock
```

These days I would usually pick Poetry or `uv` over Pipenv for new work.

# Tool 8: `uv`

`uv` is a newer, very fast Python package and environment manager.

Install:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Create venv:

```bash
uv venv
```

Activate:

```bash
source .venv/bin/activate
```

Install packages:

```bash
uv pip install requests
```

Install requirements:

```bash
uv pip install -r requirements.txt
```

Freeze:

```bash
uv pip freeze
```

Install editable project:

```bash
uv pip install -e "opt/evck"
```

Compile requirements, like pip-tools:

```bash
uv pip compile requirements.in -o requirements.txt
```

Sync exactly:

```bash
uv pip sync requirements.txt
```

This is probably the tool I’d recommend learning next after `venv` + `pip`.

It is fast, clean, and works with existing `requirements.txt` projects.

# Tool 9: `pipx`

`pipx` is for installing Python command-line tools globally but isolated.

Use `pipx` for tools like:

```text
poetry
black
ruff
httpie
pre-commit
```

Install pipx:

```bash
python3 -m pip install --user pipx
python3 -m pipx ensurepath
```

Install a tool:

```bash
pipx install poetry
pipx install ruff
```

Run without installing permanently:

```bash
pipx run cowsay hello
```

The idea:

- project dependencies go in `.venv`
- global CLI tools go through `pipx`

This keeps your project environments cleaner.

# Tool 10: `pyenv`

`pyenv` manages Python versions.

Useful when one project needs Python 3.10 and another needs Python 3.12.

Install on macOS usually:

```bash
brew install pyenv
```

Install Python:

```bash
pyenv install 3.11.9
pyenv install 3.12.3
```

Set local version for a project:

```bash
cd my-project
pyenv local 3.11.9
```

This creates:

```text
.python-version
```

Then:

```bash
python -V
```

will show that project’s chosen Python version.

Common strong setup:

```bash
pyenv local 3.11.9
python -m venv .venv
source .venv/bin/activate
```

So:

- `pyenv` chooses Python version
- `venv` isolates packages

# Tool 11: `direnv`

`direnv` automatically activates environment settings when you enter a directory.

Install:

```bash
brew install direnv
```

Add shell hook, for zsh:

```bash
echo 'eval "$(direnv hook zsh)"' >> ~/.zshrc
source ~/.zshrc
```

In project root, create `.envrc`:

```bash
source .venv/bin/activate
```

Allow it:

```bash
direnv allow
```

Now whenever you `cd` into the project, your venv activates automatically.

Very useful, but be careful: `.envrc` can run shell code, so only `direnv allow` projects you trust.

# My personal recommendation

Learn these in this order:

1. `venv`
2. `python -m pip`
3. `pip freeze`
4. `pipdeptree`
5. `pip-tools`
6. `pipx`
7. `pyenv`
8. `uv`
9. Poetry

For professional daily work, the strongest practical combo is:

```text
pyenv + venv + pip-tools + pipx
```

or the newer fast combo:

```text
pyenv + uv + pipx
```

For your current project, do not jump to Poetry yet. First make the existing `setup.py`, `.venv`, and requirements files healthy. Then upgrading to `pyproject.toml` or `uv` will make much more sense.

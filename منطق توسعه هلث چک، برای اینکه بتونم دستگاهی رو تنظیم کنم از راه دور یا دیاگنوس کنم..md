Yes — you can diagnose this remotely quite well.

Your installation shows this Orange Pi is running:

- Xorg
- Openbox
- Chromium kiosk
- systemd services like `evck-gui`, `evck-kiosk`, `evck-monitor`

So a “monitor problem” can actually be one of these:

1. HDMI cable / monitor disconnected  
2. HDMI detected but no valid mode/resolution  
3. Xorg not running  
4. Kiosk app/Chromium crashed  
5. GPU/DRM driver errors  
6. High temperature causing throttling or display instability

## 1) First: check if HDMI is physically detected

Run over SSH:

```bash
for f in /sys/class/drm/*HDMI*/status; do echo "$f: $(cat "$f")"; done
```

If you get:

- `connected` → monitor is detected
- `disconnected` → cable/monitor/port issue
- `unknown` → driver or board-specific issue

Also check available modes:

```bash
for f in /sys/class/drm/*HDMI*/modes; do echo "=== $f ==="; cat "$f"; done
```

If modes exist, the display EDID is being read.

## 2) Check what Xorg thinks

Because your setup uses Xorg/Openbox/Chromium, run:

```bash
DISPLAY=:0 xrandr --query
```

Possible outcomes:

- `HDMI-1 connected 1920x1080...` → X sees the display
- `HDMI-1 disconnected` → X sees no monitor
- `Can't open display` → X is not running or wrong display

Also test whether X is alive:

```bash
DISPLAY=:0 xset -q
```

If that works, X is up.

## 3) Check if the kiosk stack is running

Your install enables multiple services. Check them:

```bash
systemctl --no-pager --full status evck-gui evck-kiosk evck-monitor
```

Also:

```bash
ps -ef | grep -E 'Xorg|openbox|chromium' | grep -v grep
```

This tells you whether the screen is blank because HDMI failed, or just because X/Chromium died.

## 4) Check kernel display errors

Very important:

```bash
dmesg -T | grep -Ei 'hdmi|drm|display|edid|gpu'
```

Look for things like:

- EDID read failed
- connector disconnected
- mode set failed
- DRM errors
- GPU hangs

And Xorg logs:

```bash
grep -Ei '(EE|WW|HDMI|drm|modeset)' /var/log/Xorg.0.log 2>/dev/null
```

If that file doesn’t exist, try:

```bash
journalctl -b | grep -Ei 'Xorg|hdmi|drm|modeset'
```

## 5) Check CPU temperature remotely

Use:

```bash
cat /sys/class/thermal/thermal_zone0/temp
```

This usually returns millidegrees Celsius.

Example:
- `65000` = 65°C

Human-readable:

```bash
awk '{printf "%.1f°C\n", $1/1000}' /sys/class/thermal/thermal_zone0/temp
```

If your board has multiple thermal zones:

```bash
for z in /sys/class/thermal/thermal_zone*; do echo -n "$z "; cat "$z/type" 2>/dev/null; cat "$z/temp" 2>/dev/null; done
```

## 6) Will HDMI turn off if CPU temperature rises?

Usually: **not directly**.

On Linux / Orange Pi, high temperature normally causes:

- CPU frequency throttling
- performance drop
- GPU instability in bad cases
- app freeze or X crash in worse cases
- emergency shutdown if temperature becomes critical

But **HDMI is usually not intentionally turned off just because CPU temp goes up**.

What may happen is:

- system becomes unstable
- compositor/browser hangs
- screen becomes black
- HDMI still says “connected”

So if the display goes black during heat, it is more often:
- Xorg crashed
- Chromium froze
- GPU driver failed
- system throttled badly
- board power issue

## 7) Check if the kernel is throttling or overheating

Run:

```bash
dmesg -T | grep -Ei 'thermal|thrott|overheat'
```

And also:

```bash
journalctl -k -b | grep -Ei 'thermal|thrott|overheat'
```

This may show:
- thermal throttling
- trip point reached
- cooling device activated

For current CPU frequency:

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
```

And governor:

```bash
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor
```

If hot, you may see frequency reduced.

## 8) Best quick remote diagnosis command

Use this one-liner:

```bash
echo "=== HDMI ==="; for f in /sys/class/drm/*HDMI*/status; do echo "$f: $(cat "$f")"; done; \
echo "=== MODES ==="; for f in /sys/class/drm/*HDMI*/modes; do echo "--- $f"; cat "$f"; done; \
echo "=== TEMP ==="; awk '{printf "%.1f°C\n", $1/1000}' /sys/class/thermal/thermal_zone0/temp; \
echo "=== XORG ==="; ps -ef | grep -E 'Xorg|openbox|chromium' | grep -v grep; \
echo "=== XRANDR ==="; DISPLAY=:0 xrandr --query 2>&1; \
echo "=== SERVICES ==="; systemctl is-active evck-gui evck-kiosk evck-monitor; \
echo "=== KERNEL HDMI/THERMAL ==="; dmesg -T | grep -Ei 'hdmi|drm|thermal|thrott' | tail -n 50
```

That gives you almost everything in one shot.

## 10) A practical monitoring script you can add now

Example:

```bash
#!/bin/bash

LOG=/opt/evck/logs/display-health.log
TS="$(date '+%F %T')"

HDMI_STATUS="$(for f in /sys/class/drm/*HDMI*/status; do cat "$f" 2>/dev/null; done | head -n1)"
HDMI_MODES="$(for f in /sys/class/drm/*HDMI*/modes; do head -n1 "$f" 2>/dev/null; done | head -n1)"
TEMP_RAW="$(cat /sys/class/thermal/thermal_zone0/temp 2>/dev/null || echo 0)"
TEMP_C="$((TEMP_RAW/1000))"
X_OK="$(DISPLAY=:0 xset -q >/dev/null 2>&1 && echo yes || echo no)"
CHROME_OK="$(pgrep -f chromium >/dev/null && echo yes || echo no)"
XORG_OK="$(pgrep -x Xorg >/dev/null && echo yes || echo no)"

echo "$TS HDMI=$HDMI_STATUS MODE=$HDMI_MODES TEMP=${TEMP_C}C XORG=$XORG_OK X=$X_OK CHROMIUM=$CHROME_OK" >> "$LOG"
```

Run it every minute with systemd timer or cron.

## 11) If you want to know specifically whether “black screen” is monitor or software

Use this logic:

- HDMI `disconnected` → cable/monitor/power/port problem
- HDMI `connected`, Xorg dead → software/X crash
- HDMI `connected`, Xorg alive, Chromium dead → kiosk app problem
- HDMI `connected`, Xorg alive, Chromium alive, but user sees black → GPU/render/display mode issue
- high temp + thermal logs + freezes → likely heat-related instability, not HDMI-off logic

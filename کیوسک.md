Your kiosk stack is actually **structured pretty well**, but there are a few subtle things that can absolutely cause the kind of system lockups you described. Let’s walk through exactly how it works and where the weak points are.

---

# 1. How Your Kiosk Actually Starts

The chain is:

```
systemd kiosk.service
        ↓
startx
        ↓
~/.xinitrc
        ↓
/opt/evck/start-kiosk.sh
        ↓
chromium-browser
```

### Step‑by‑step

**systemd service**

Your service runs:

```
ExecStart=/usr/bin/startx
```

That launches the X server on display `:0`.

---

**startx**

`startx` looks for:

```
/home/orangepi/.xinitrc
```

which you showed.

---

**.xinitrc**

```
openbox &
exec /opt/evck/start-kiosk.sh
```

So:

1. Openbox starts (window manager)
2. Your kiosk script runs
3. `exec` replaces the shell with that script

If that script exits → **X session ends → systemd restarts the service**.

---

# 2. How Chromium Opens the Correct Port

Inside your script:

```
URL="http://127.0.0.1:8082"
```

and later:

```
exec chromium-browser --app="$URL"
```

So Chromium loads:

```
http://127.0.0.1:8082
```

which is **localhost port 8082**.

That means your Flask app must be running something like:

```python
app.run(host="127.0.0.1", port=8082)
```

or

```python
socketio.run(app, host="127.0.0.1", port=8082)
```

If the GUI service isn't ready yet when Chromium launches, you get a **connection error page**.

# 3. Why Your System Might Freeze

There are a few serious risk points.

---

# Problem 1 — Crash Loop Through systemd

Your `.xinitrc` uses:

```
exec /opt/evck/start-kiosk.sh
```

Your script uses:

```
set -euo pipefail
```

This is dangerous in kiosk environments.

Example:

```
xrandr fails
```

→ script exits  
→ X session ends  
→ systemd restarts it  
→ loop repeats

Your system may then:

- restart X dozens of times
- eat CPU
- kill SSH responsiveness

---

# Problem 2 — Chromium GPU Flags on Orange Pi

You enabled aggressive GPU acceleration:

```
--enable-gpu-rasterization
--ignore-gpu-blocklist
--enable-zero-copy
--use-gl=angle
--use-angle=gl
--enable-native-gpu-memory-buffers
--enable-accelerated-video-decode
```

On **Orange Pi Zero 2W (Allwinner H618)** this is risky.

Many ARM GPU drivers are unstable with Chromium.

This can cause:

- X crashes
- GPU hangs
- entire system lock

This is **very likely one of your freeze causes**.

---

# Problem 3 — Killing the Chromium Profile Every Boot

You do:

```
rm -rf "$PROFILE_DIR"
```

That is safe, but if Chromium starts twice concurrently (restart race), it may corrupt.

Rare but possible.

---

# Problem 4 — Flask Might Not Be Ready Yet

Chromium launches immediately.

Your GUI service might still be booting.

Chromium will show:

```
ERR_CONNECTION_REFUSED
```

and never reload.

---

# Problem 5 — Log File Could Block

You log to:

```
/opt/evck/logs/chromium.log
```

If the directory doesn't exist or fills the disk, Chromium fails.

---

# 4. What I Would Fix Immediately

These changes make the kiosk **much more robust**.

---

## Fix 1 — Add GUI dependency to kiosk service

Your kiosk should wait for the backend.

Edit:

```
/etc/systemd/system/kiosk.service
```

Add:

```
After=gui.service
Requires=gui.service
```

---

## Fix 2 — Delay Chromium Start

Add before Chromium launch in your script:

```
sleep 5
```

or smarter:

```
until curl -s http://127.0.0.1:8082 >/dev/null; do
  sleep 1
done
```

---

## Fix 3 — Remove Dangerous GPU Flags

Replace this section:

```
--enable-gpu-rasterization
--ignore-gpu-blocklist
--enable-zero-copy
--use-gl=angle
--use-angle=gl
--enable-native-gpu-memory-buffers
--enable-accelerated-video-decode
--enable-features=V4L2VideoDecoder,CanvasOopRasterization,PlatformHEVCDecoderSupport
--enable-gpu-memory-buffer-video-frames
```

with the **safe version**:

```
--disable-gpu
--disable-software-rasterizer
```

ARM SBC GPUs often behave better without Chromium GPU acceleration.

---

## Fix 4 — Ensure Logs Directory Exists

Add at the top of your script:

```
mkdir -p /opt/evck/logs
```

---

## Fix 5 — Make Script Less Fragile

Replace:

```
set -euo pipefail
```

with:

```
set -u
```

This prevents harmless commands from crashing the entire session.

---

# 5. A Hidden Problem I Suspect

Your kiosk service probably has:

```
Restart=always
RestartSec=2
```

This is **too aggressive**.

Change to:

```
Restart=always
RestartSec=10
StartLimitIntervalSec=60
StartLimitBurst=3
```

Otherwise if X fails → the CPU gets hammered restarting it.

---

# 6. Your Kiosk Design (Architecturally)

Honestly, this design is **pretty solid**:

```
systemd
   ↓
X
   ↓
Openbox
   ↓
kiosk script
   ↓
Chromium
   ↓
Flask GUI
```

That's exactly how many embedded kiosks are built.

The issues are **edge‑case stability**, not architecture.
